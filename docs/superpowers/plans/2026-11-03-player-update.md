# План обновления Impuls 1.1

Спецификация: ../specs/2026-11-03-player-update-design.md

Общие ограничения: GTK4 и существующий пассивный UI; без сетевых вызовов из UI; без открытых токенов; сохранить защиту от устаревших ответов и корректность повторяющихся треков. Пользователь выбрал ретро нулевых. Работаем в предоставленной директории, без коммитов, публикации и внешних изменений.

1. GUI: серебро/синий, типографика, двухстрочные строки и компактная колонка альбома, активная навигация, удобный размер кнопок; refresh/play-all/shuffle-list; mute и меню/горячие клавиши/контекстные действия. Файлы ui.py, style.css, tests/test_ui*.py.
2. API/playback: refresh_view(), play_all(shuffle=False) как публичные callbacks, корректное кеширование и повтор запросов; исправление отказов toggle. Файлы controller.py/service.py/player.py, соответствующие тесты. GUI вызывает refresh_view и play_all.
3. Tray/lifecycle: tray.py, app.py, tests/test_tray.py, tests/test_app.py. UI close-request сначала вызывает actions['close_window']() и скрывает окно при True, без очистки источников. App добавляет hide_window и quit; set_tray_available(bool) в UI. При доступном хосте закрытие скрывает; при потере хоста скрытое окно возвращается. Меню синхронизирует track/playing; без трея обычное закрытие.
4. Preferences: settings.py с безопасным JSON и тестами; Settings.load(), save(values), defaults и валидация. App применяет volume/quality/equalizer, сохраняет при shutdown. Без токенов.
5. Интеграция: полный прогон тестов, отдельная сессия D-Bus и GTK-снимки, ревью субагентом, исправления, документация версии и сборка. Явно описать ограничения проверки реального аккаунта/трея.

Риски проверки: отсутствие трея у GNOME; исчезновение хоста; закрытие при pending render; refresh во время смены аккаунта; настройки с испорченным JSON; узкое окно и длинные кириллические названия; ошибки Gst при pause/resume.
